# 계획 문서 형식 (plan-format)

Claude(오케스트레이터)가 작성하고 실행자(`handoff run`이 고른 Codex·Antigravity·Claude)가 소비하는
계획 파일의 형식. 위치는 대상 프로젝트의 `docs/superpowers/plans/YYYY-MM-DD-<주제>.md`
(superpowers writing-plans 규약과 동일 — 계획 위치를 한 곳으로 통일한다).

## 형식

```markdown
# <주제> 계획

## 태스크

- [ ] T1: <목표 한 문장>
  - 대상: <생성/수정할 파일 경로 — 파일 단위로 전부 나열>
  - 배경: <인터페이스 시그니처 · 호출 관계 · 지켜야 할 관례 · 참고할 기존 파일 — 구현 코드는 쓰지 않는다>
  - 검증: `<실행 가능한 커맨드>` → <기대 결과>

- [ ] T2: ...
```

## 규칙

1. **`검증:` 줄이 없는 태스크는 실행자에게 넘기지 않는다.** 실행 가능한
   커맨드와 기대 결과가 품질 게이트의 전부다.
2. 태스크는 독립적으로 검증 가능한 최소 단위로 자른다.
3. 체크박스(`- [x]`) 갱신은 검증 커맨드를 직접 실행한 오케스트레이터만 한다.
   실행자는 체크박스를 건드리지 않는다.
4. Linear 큐(Layer B)로 승격할 때는 태스크 1건 = 이슈 1건으로 옮기고,
   `검증:` 줄을 이슈 본문에 반드시 포함한다.
5. **`대상:`은 파일 단위로 정확히 적는다.** worktree에서 본체로 반입할 때
   이 경로만 옮기고 나머지는 버리므로, 빠진 파일은 결과에서도 빠진다.
6. **계획에 구현 코드를 쓰지 않는다.** 구현은 실행자 몫이다(2026-10-01
   사용자 결정). 태스크는 목표 ·
   대상 · 배경(인터페이스 시그니처, 호출 관계, 관례, 참고 파일) · 검증까지만
   적는다. 코드 블록은 `검증:` 커맨드와 시그니처 선언(함수명 · 파라미터 ·
   반환 타입 · 테이블/컬럼명)에만 허용한다. 테스트도 테스트 이름과 단언할
   행동만 적고 테스트 코드는 쓰지 않는다. 예외는 버그 수정처럼 바뀔 줄이
   특정되는 태스크로, 행 번호와 바꿀 내용 한 줄 수준까지 허용한다.

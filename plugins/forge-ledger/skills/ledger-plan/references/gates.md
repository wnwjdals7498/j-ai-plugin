# 이끄는 방식과 게이트

| 구분 | 내용 |
| --- | --- |
| 안내(막지 않음) | 스킬의 질문 순서. PRD가 빠진 단위 프로젝트에서는 `next`가 계획 작업을 먼저 제안. 세션 시작 요약의 빠진 문서 수. 대시보드 S4·S9. 게이트 예고(cycle 종료 3일 전, Telegram 포함) |
| 게이트 1 단계 종료 | 구현 2·3·5(단위)와 구현 1·4·6(저장소)이 이번 cycle 시작 뒤 갱신됐거나 "변경 없음: 이유"가 있다. 구현 7에 다음 단계 범위와 cycle이 있다. 필요 시점이 이번 단계인 미결 질문이 0건이다. 형식 검사를 통과한다 |
| 게이트 2 릴리스 | 구현 1·4·6·8·9가 마지막 릴리스 뒤 갱신됐거나 "변경 없음: 이유"가 있다. 릴리스에 들어가는 단위 프로젝트마다 게이트 1 기록이 있다. 결정 줄의 Plane 수정 시각 불일치가 0건이다. 전체 형식 검사와 비밀값 검사를 통과한다 |
| "변경 없음" 기록 | 게이트가 갱신되지 않은 문서마다 이유를 묻고, 구현 7 단계 항목의 그 단계 행에 남긴다 |
| 막지 않는 곳 | 작업 착수, `plan fix`, 커밋, PR, Plane 화면 작업. 훅이 막는 것은 비밀값 쓰기 하나뿐이고 계획서와 관계없다 |
| 우회(Q14 기본값) | `--override "<사유>"`. 이력 줄 override, 알림 M12, Telegram으로 남긴다. 검사 불가(도구 연결 실패, 종료 코드 2)도 멈춤으로 보고 우회할 수 있다 |
| 한계 | 게이트는 플러그인 명령에서만 막는다. Plane 화면에서 cycle을 닫거나 Gitea에서 직접 태그를 만들면 막지 못하고 M10·M12로 알린다. CI 필수 상태 검사로도 막을 수 있는지는 P0에서 확인한다 |

# 2단계 시험·로그·증거 실행 계획

모든 항목은 **예정**이다. 세부 시나리오는 작업 문서에 두고 이 문서는 실행 방식·담당·증거·전체 범위를 연결한다. 시험 정의 버전과 실제 결과 manifest는 분리한다.

## 시험 실행 방식

| 시험 ID·담당 | 실행·실패 주입 방식 | 판정할 실제 관찰 |
|---|---|---|
| Q0-CONTRACT·메인 | 필드/전이/소유/이관/시험 교차 검토 | 미정 지원을 확인 항목으로 분리, 중복 원본·의존 순환 없음 |
| P2-DATA-01~05·Q1 | schema 2 격리 DB·실제 파일, 독립 프로세스 CAS 경쟁, 이관 각 단계 종료, 빈 root 복원 | ID/claim/관계/hash/요청 결과 보존, 부분 변경 rollback |
| P2-TREE-01~08·Q2 | 정상·경계·위임·잘못된 관계 fixture, validator 호출, 문서 생성/graph 재조회 | 제한·세 종료 조건·근거/대전제·다대다 추적·초안/확정 구분 |
| P2-TREE-09·Q2/Q9 | 실제 상위 역할 스킬로 요구→선택/조사→두 트리→문서 실행 | 의미 적합성 메인 검토, 원 요구 누락/확장·근거 부족 명시; JSON 왕복만으로 대체 금지 |
| P2-STEP-01~10·Q3 | 탐색/구현 지시·조회/내보내기·늦은 결과·완료 검토, 실제 DB/리소스 | 원문 제외, 버전 고정·상속·독립 완료 판단·가지 무효화 |
| P2-ROUTE-01~07·Q4 | policy/capability/권한·비용 미상 조합, 호출 spy + 실제 지원 snapshot | 사용자 우선·절약형·native 우선/대기·CLI/SDK→API 순서, 실제 모델 기록 |
| P2-LOCK-01~05·Q5 | 독립 프로세스 barrier로 동시 요청, 동일/겹친/독립/다중 범위·실행 중 확장 경쟁, 내용 접근 계측 | 단일 점유·독립 병렬·부분 점유 없음·새 영역 확보 전 read/write 없음 |
| P2-RUN-01~05·Q5 | 실제 짧은 테스트 자식 프로세스, intent/handle/결과/통지 사이 강제 종료, 중복 receipt·재시도 | 재처리 일치·상태 복구·최대 2회 재시도·미확인 실행 재호출 없음 |
| P2-RUN-06~08·Q6/Q5 | 실제 runner 연결·중복/유실 callback·polling·역순 관찰/결과 | 외부 경로 분리·결과 영속화·종료 상태 역행 없음 |
| P2-CANCEL-01~03·Q5/Q6 | 종료 지연 자식·미응답 runner·메인 재개·취소/결과 경쟁 | 종료 전 lock 유지, 소유 자식 종료 확인·결과 보존·중복 실행 없음 |
| P2-API-01~04·Q6 | 비허용은 호출 계측, 계약 fixture와 허용된 실제 제공자 호출 분리 | 인증/허용·지원 규약·선택지 결과·도구 게이트·오류/응답 유실 처리 |
| P2-GIT-01~06·Q7 | 임시 Git 저장소에서 commit 추가/동일/dirty/브랜치/이력 변경, 비Git 프로젝트 | 지정 시점만 분석, 반영 후 기준 갱신, 변경/owner 보존·영향 제한 |
| P2-DATA-11~14·Q7 | 파일 게시/DB 반영 사이 종료·손상 증거·후속 실패·stale 결과 | journal 복구·hash 확인·현재 완료 보호·유효 검증 재사용 |
| P2-OBS-01~08·Q8 | 제어 가능한 시간+실제 파일, 로그 쓰기 실패·회전·민감값·정리 중 종료/새 참조 경쟁 | 60초 관찰·timestamp 분리·쓰기 실패 구별·보존 예외·참조 무결성 |
| P2-NATIVE-01~05·Q6 | 실제 제품의 capability/대상 모델·도구/권한·native 호출·취소/재개 확인 | 선언 지원의 근거·실제 handle/모델·미지원/미확인/차단 구별 |
| P2-NATIVE-21~26·Q9 | Codex/Claude/OpenCode 격리 설치·새 세션·배정/결과·업데이트/재설치 | 배포물에서 실제 경로 재현, data 보존, fixture와 실제 결과 분리 |
| P2-DATA-16·Q9 | 두 트리→Work/Item/Step→독립 병렬/의존 작업→증거 검토→통합 완료 | 전체 요구 추적·부분 결과 구분·통합 후 영향 시험·명시 최종 검토 |

Q3의 Git/이관 시나리오처럼 같은 동작을 참조하는 시험은 Q1/Q7 결과와 정확한 적용 조건이 일치하면 증거를 연결한다. P2-STEP-09/10은 해당 기반을 소비하는 연계 시험으로 G4에서 확인한다. G2/G3의 계약 대역 시험을 실제 연계 성공으로 표시하지 않는다. 시험 ID가 다르다는 이유만으로 동일 실행을 반복하지 않는다. 검증 정의·입력·대상·환경·증거가 다른 시험은 각각 실행한다.

## 제품·실행 경로 행렬

| 대상 | 필수 확인 |
|---|---|
| Codex / Claude Code / OpenCode 각각 | 설치 버전·새 세션·대상 모델 지정·필요 도구/권한·실제 지원 경로·결과 회수·취소/종료 확인·재개 |
| 동일 에이전트 native | 지원 시 우선, 슬롯 부족 대기, 부모/자식 ID·실제 모델 기록 |
| 외부 CLI/SDK | 허용 경로 지정·subagent 미지원 시 선택, 프로세스/세션 식별·출력 정규화·종료 확인 |
| 직접 API | 연결된 실제 제공자별 조사/선택 결과, 금지 설정 무호출, 코드 도구 미구현 시 코드 작업 활성화 금지 |

제품마다 모든 native 기능을 제공한다고 가정하지 않는다. 미지원 조합을 올바르게 차단/허용 경로로 처리하는 시험은 통과할 수 있지만 **요구된 실제 실행 경로의 미실행**을 대신하지 못한다. 전체 코드 작업 범위에 직접 API를 선언하려면 도구 실행·권한·격리 시험까지 필요하다. `freeLLMAPI`는 이름만으로 호환을 단정하지 않고 실제 제공자 규약을 확인한다.

## 코드동작 로그 확인

작업 문서의 event명은 관찰 지점 계약이다. 구현 시작 시 메인이 최종 event registry·허용 필드를 공유한다. 진단 로그를 통해 상태가 맞다고만 판단하지 않고 DB/프로세스/파일/Git 실제 상태와 대조한다.

| 기능 | 대조할 로그 ↔ 실제 상태 |
|---|---|
| 요청/저장 | request/correlation·revision·transaction 결과 ↔ 한 번의 DB 변경·이벤트·재처리 결과 |
| planning | node/plan/graph 버전·결정/증거 refs ↔ 문서/graph·지시 hash·현재 기준 |
| routing/runner | requested/actual model·route·capability·run/handle refs ↔ 실제 호출 인수/receipt; 비밀 정제 |
| Queue/lock | 대기 이유·소유·허용 전이·retry·cancel/reconcile ↔ 점유 행·실행 상태·종료 확인 |
| Git/검증 | 이전/새 기준·영향·재사용 이유 ↔ 실제 Git diff·dirty·근거 유효성 |
| 운영/정리 | last_seen/last_changed·실패 구분·후보/정리 receipt ↔ snapshot·보존 파일·참조·삭제 결과 |

시간 변경·외부 응답 유실을 재현 가능하게 주입한다. 신속한 시간 경계 시험은 제어된 시계로 수행하되 실제 로그 회전·프로세스 취소·동시 점유도 확인한다. 임의 sleep에만 의존해 경합 성공을 주장하지 않는다.

## 증거·완료 판정

manifest 필수 의미: 시험 ID/정의 버전·수용 기준, 실제/fixture 계층, 제품/모델/경로, 실제 명령/도구 호출 참조·종료 코드, 시작/종료, commit/dirty·환경/의존성/입력/설정 지문, 지시/계획 버전, request/correlation/run·증거 refs, pass/fail/blocked/not_run·재사용 이유.

명령·제품 원응답에 비밀이 있으면 정제하고 재현에 필요한 안전한 부분만 보존한다. 모델 요약은 실제 로그·코드 상태·시험을 대체하지 않는다. 자료가 삭제·손상되거나 후속 실패가 있으면 재사용 자격을 다시 판단한다.

| 2단계 요구군 | 소유·완료 근거 |
|---|---|
| 두 트리·자원/프레임워크·기능명세·문서/graph | Q2 + P2-TREE |
| Work/Item/Step·태그·지시·단계별 완료 | Q1/Q3 + P2-DATA/P2-STEP |
| 설정·모델 역할·native 우선·허용 경로 | Q4/Q6 + P2-ROUTE/P2-API/P2-NATIVE |
| Queue·lock·병렬/의존·중단/재개 | Q5/Q6 + P2-LOCK/P2-RUN/P2-CANCEL |
| Git 우선·변경 영향·근거 재사용 | Q3/Q7 + P2-GIT/P2-DATA |
| 진행·로그·보존·실제 제품 통합 | Q8/Q9 + P2-OBS/P2-NATIVE/P2-DATA-16 |

최종 메인은 전체 요구 → 작업 묶음 → 시험/증거 매핑을 확인한다. 구현·관련 회귀·제품 수용이 충족되고 필수 fail/blocked/not_run이 해소되어야 G4가 열린다. 기존 1단계 실측 결과는 현재 코드 변경의 회귀 결과와 구별한다.

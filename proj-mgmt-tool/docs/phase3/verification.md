# 3단계 시험·로그·인계 명세

상태: **예정 시험**. [기능 명세](contracts.md)의 goal을 실제 동작으로 판정하기 위한 연결 기준이다. 현재 2단계 시험의 통과 수를 이 기능의 성공으로 사용하지 않는다.

## 기능별 시험·관찰

각 기능은 `P3-F번호-01~03`의 고유 시나리오를 정의한다. 세부 기대 결과는 담당 명세가 원본이고, 아래는 실제 실행 방법과 전체 추적 관계다.

기존 방향 문서의 P3-INPUT/GRAPH/RENDER/CONTEXT/REUSE/CONTROL/BATCH/HOST/MEASURE는 시험 **범주**다. 위의 기능별 ID를 해당 범주에 연결한다. 동일 정의/조건/대상의 실행 증거를 다른 관문에서 참조해도 독립 구현/실제품 확인을 대체하지 않는다.

## 실행 계층과 증거

1. 순수 규칙: 명확한 graph·변경·문맥·오류 fixture. fixture 의미 판단을 실제 모델 품질로 표시하지 않는다.
2. 본체 통합: 실제 격리 SQLite/Git/파일·독립 프로세스·로컬 실행/결과/취소. DB/파일/외부 실행 경계마다 실패 주입.
3. Host 통합: 실제 로컬 Host와 독립 clients, HTTPS·인증·HTTP·DB/파일 관찰. in-process 대역은 이 계층의 통과가 아니다.
4. 제품/환경: 설치된 CLI/native 세션·승인된 별도 환경에서 확인. 로컬 fixture·실제 모델·별도 Host를 구별한다. 직접 모델 API는 제외하고 외부 모델 전송은 기존 사용자 선택을 따른다.

필수 접근/제품/권한이 없으면 해당 ID는 blocked, 미실행은 not_run, 실제 실패는 fail이다. 테스트에서 프로세스/네트워크를 차단할 때 승인된 시험 자원만 사용하고 global 방화벽·사용자 설정·운영 DB를 임의 변경하지 않는다.

manifest에는 기능/시험/정의 버전·수용 기준·계층·SourcePin·환경/도구/설정/입력/모델 지문·실제 command/action와 종료 코드·시각·request/event/job/run/batch·정책/묶음/매핑 버전·상태·증거 refs·재사용/미상 이유를 남긴다. token 미제공은 null/unknown이며 byte 추정과 구별한다.

## 코드동작 로그 확인

로그에서 성공이라고 출력됐다는 이유만으로 통과하지 않는다. F1/F4는 원본/파일 hash·journal과, F2/F3/F5는 실제 참조/권한·index/source 버전과, F6/F8/F9는 DB 점유·물리 실행/handle·실측 receipt와, F11~F14는 실제 Host 상태/HTTP·권위 namespace와 대조한다. F10/F15는 그 증거와 총 비용/품질 판정을 연결한다.

공통 필드는 [F0 계약](contracts.md)을 따른다. feature event명은 제안이며 구현 착수 때 메인이 registry·허용 필드를 확정한다. 같은 메시지를 모든 층의 업무 이력에 중복 기록하지 않는다. 반복 관찰은 최근 snapshot, 의미 있는 변경은 업무 이벤트, 실측은 증거로 분리한다.

## 통합 관문·병렬 배정

| 관문 | 확인할 내용 | 다음 소비 |
|---|---|---|
| G0 공통 착수 | F0 계약·소유/호환·측정 기준 확보 | F1/F7 |
| G1 데이터 기반 | F1→F2→F3의 자체·실제 연계 시험 | F4/F5/F6 |
| G2 독립 기능 | F4/F5/F6 및 F7 자체 규칙/계약 시험·인계 | 준비된 F8/F9; 연계 시험은 G3 |
| G3 로컬 통합 | F8/F9 연결, F10의 F1~F9 전체 동작/효율·품질 확인 | F11 |
| G4 Host 기반 | F11의 실제 저장·인증·호환·동시성 경계 | F12/F13 |
| G5 환경 통합 | F12/F13와 F14의 실제 연결/이관/단절/재개 | F15 |
| G6 최종 수용 | F15 전체 기능·제품/환경·실측·미해결 확인 | 완료 기록·배포 인계 |

F2의 문서 의존 index와 F3의 영향 규칙은 F0의 형식/fixture로 준비할 수 있다. 실제 F4 manifest/문서 연계는 G3에서 확인한다. F8은 단일 Step 제어부터, F9는 그 위의 묶음으로 확장해 순환 선행을 만들지 않는다.

메인은 공통 스키마·공개 서비스/CLI·로그/시험 registry·통합·Git을 소유한다. F4/F5/F6, F12/F13은 독립 영역에서 병렬 가능하며 `gpt-6-luna` 최대 3개와 실제 실행 한도 내에서 배정한다. 같은 공유 영역을 여러 작업자가 수정하지 않는다. 소유자 간 계약 변경은 이유/영향/이관/시험을 메인에게 전달한다.

## 인계·완료

작업 지시는 기능/Step ID·목적·변경 범위·goal/non-goal·의미 I/O·방법/근거·선행·Test/로그·완료/자율 경계를 포함한다. 파일별 줄 수정 목록으로 만들지 않는다. 작업자는 실제 변경 영역, 계약/지시 버전, 기준별 결과, 실제 시험/종료 코드/commit·dirty·증거, 잔여 문제·다음 행동을 반환한다.

G6는 승인된 전체 범위의 구현/실제 연계·필수 시험·현재 증거·효율/품질 판정과 미해결 fail/blocked/not_run을 확인한다. 필요한 환경이 없는 항목은 성공 예외로 바꾸지 않으며 전체 수용 미충족으로 보고한다. 실제 배포/전환은 사용자에게 이미 허용된 범위와 확인된 운영값·권한을 따른다.

# F10 로컬 통합·효율 판정 명세

상태: **예정 구현·시험**. 범위/선행은 [기능 목록](README.md), 공통 값·권위·안전/로그는 [F0 계약](contracts.md)을 따른다.

## 목적·범위·goal

- **목적·이유:** 정형 변경·문서·문맥·재사용·실행 제어·묶음 배정이 연결돼 실제 토큰/시간을 줄이는지 확인한 뒤 Host 연결의 기준으로 고정한다.
- **추가:** 공통 정의의 로컬 시나리오 실행·실측 집계·기준 대비 비교·정책 조정 후보·Host 소비용 검토된 계약 버전.
- **수정:** 기존 메인/스킬/CLI·실행/검증/리소스 흐름을 F1~F9 서비스에 연결하고, 실제/추정/미상을 표시하는 결과 수집과 문서 반영을 확장한다.
- **삭제/축소:** 전체 문서/graph/로그 재전달·불필요한 AI 제어 호출·같은 검증 반복을 적용성이 확인된 부분에서 줄인다. 품질/안전 기준과 원 증거는 유지한다.
- **goal:** 같은 요구·환경·모델/역할에서 정합한 결과와 기능별 증거가 있고, 감소/증가한 비용과 원인을 측정해 필요한 정책을 조정한다.
- **non-goal:** 고정 절감률 보장, 모델 변경으로 생긴 비용 차이를 기능 최적화로 주장하기, 사용자 운영 데이터로 파기 시험, Host를 먼저 만들어 로컬 효과와 섞기.

## input / output

| 방향 | 값의 의미·타입·제약 |
|---|---|
| input 기준 사례 | 신규 계획·부분 변경·재개·병렬 조사·모호한 요구·실패/재시도의 사례 ID/정의/기준 참조 배열 |
| input 전후 조건 | 동일 요구/완료 기준·commit/dirty·환경/의존/설정·모델/역할·범위·측정 정의 버전의 지문 객체 |
| input 정책 | 문맥 예산/상세 조회·출력 축약·배정/재시도·캐시 조건의 버전별 선택값. 직접 비밀값 제외 |
| input 실제 기록 | 실행/도구 호출·관찰·상태·시험·근거·문자/byte/시간/제공된 token 정보의 추적 참조 |
| output 기능 판정 | F1~F9 기준별 pass/fail/blocked/not_run·계약 호환/영향·증거·미해결 |
| output 비교 | token/호출/조회/재조사/재검증/재시도/재질문/시간·누락/오판/기준 충족의 전후 결과와 비교 가능 여부 |
| output 개선 후보 | 비용 증가 원인·조정할 정책·영향 기능·다음 확인 기준. 효과 없는 기능을 성공으로 숨기지 않음 |
| output Host 인계 | 검토된 공통 서비스·저장 계약·지원/미확인·유효 시험/증거·아직 실패/차단된 범위 |

토큰 정보가 없으면 미상, 문자/byte 추정은 별도 필드다. 캐시 사용량·응답 크기·모델 호출 수를 동일 지표로 합치지 않는다. 총비용에는 추가 상세 질의·요약/문맥 생성·실패/재시도·재검토 비용도 포함한다. 임의 요금/가격을 추정하지 않는다.

## 구현 방식·기술·의존

Python 시나리오 조합·구조화 로그/manifest·실제 SQLite/파일/프로세스와 기존 검증 지문을 사용한다. 재현 사례의 원본 기준을 F0에서 먼저 고정하고, F10에서 최적화 흐름을 비교한다. 별도 분석 서비스/직접 모델 API를 만들지 않는다.

문서 변경·영향 계산·역참조/문맥 무효화 → 필요 범위 전달 → 재사용/새 배정 → 실측 결과·메인 검토 → 다음 세션 재개를 연결한다. 동일 원본의 부분/전체 생성과 묶음/개별 배정에서 같은 목표·판정이 나오는지 확인한다.

기계 반복 규칙은 결정적 fixture로 검증하고 실제 네이티브 모델에서 문맥 부족/오판 여부를 별도로 확인한다. CLI 제품/전달 시험은 승인된 로컬 응답 fixture를 사용할 수 있으나 실제 모델 품질 성공으로 집계하지 않는다. 직접 외부 제공자 전송은 기존 사용자 선택을 따른다.

**선행:** F4·F9(그들의 F0~F8 의존 포함). 기능별 자체 시험·계약 인계가 있어야 한다. **소비자:** F11·F15·메인. **소유:** 메인이 통합·효율 판정을 소유하고 결함 수정은 해당 기능 소유자에게 배정한다. 구현 작업자는 `gpt-6-luna`, 독립 범위만 최대 3개 병렬이다.

## 코드동작 Test 방식

| ID | 시험 방식 | 관찰 기준 |
|---|---|---|
| P3-F10-01 | 실제 격리 저장소/DB/프로세스로 신규·변경·재개·병렬 흐름 연결 | 같은 목표/원본에 일관된 문서/Step/결과, 필수 기준·금지 범위·증거 보존 |
| P3-F10-02 | 기준/모델/환경 불일치·token 미제공·추가 질의·반복 실패·일부 차단 사례 | 비교 불가·미상/추정 구분, 전체 비용에 재작업 포함, fixture를 모델 품질로 집계하지 않음 |
| P3-F10-03 | 문맥 부족·입력 재제출·캐시 미적중·과도한 묶음으로 비용 증가 후 정책 조정 | 실제 원인/효과·품질 기준 확인, 최적화 전 기준 보존, 관련 재검증만 수행 |

기존 231개 통과 기록은 2단계 사실이며 이 신규 시험의 성공이 아니다. 성능 값은 같은 조건의 여러 사례/반복에서 편차와 함께 해석한다. 실제 모델 사용량 정보가 없으면 byte/호출/시간·품질 관찰만 입증하고 token 절감률은 미확인으로 남긴다.

## 코드동작 로그·완료·인계

이벤트: `efficiency.scenario_started/completed`, `efficiency.comparison_rejected`, `efficiency.policy_assessed`. 사례/기준/정의·task/run·SourcePin·모델/역할·정책·실제/추정·캐시 적중/무효화 이유·규모/시간/호출·비교 가능·기준 결과·증거 참조를 기록한다. 전체 대화/문맥을 측정 로그에 재저장하지 않는다.

측정 집계는 실제 제품 제공 메타데이터·실행/도구 receipt·증거 manifest와 대조한다. 성공 요약만으로 품질/완료를 판정하지 않는다. 진단 실패와 업무/증거 실패의 처리는 F0를 따른다.

**완료:** 로컬 전체 기능이 실제 의존으로 연결되고 필수 실패/차단이 해소된다. 측정 가능한 대표 사례에서 감소/증가·정책 선택·품질 한계를 보고하고 Host가 소비할 계약을 메인이 확정한다. token 미상은 대체 지표로 보고하되 임의 성공값을 만들지 않는다.

**인계:** 조건 지문·실제 변경 범위·기준별 결과/정의·명령/종료 코드·증거·비교·미해결·소비자 계약을 전달한다. **자율:** 승인 범위의 집계/표현·재현 사례와 정책 조합. **메인 판단:** 비교 기준 변경·품질 기준 축소·새 모델/권한·Host 선행 착수·측정 없이 완료 승격.

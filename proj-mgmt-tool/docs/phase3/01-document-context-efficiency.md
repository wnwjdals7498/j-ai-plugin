# 3단계: 문서·문맥 효율화 계약

2026-10-02 합의. **예정 구현 규격**이며 현재 제공되는 operation 목록이 아니다. [3단계 전체 계획](../03-hosted-storage.md)에 포함하며, 로컬에서 완성한 기능을 이후 Host 저장 연결에 재사용한다.

## 목적·goal·범위

- **목적:** AI의 전체 문서 재작성·반복 읽기·중복 조사·불필요한 호출을 줄여 토큰과 시간을 절약한다.
- **추가:** 노드/관계 변경 입력, 관계 기반 영향 조회, 부분 문서 생성, 작업별 문맥·재개 묶음, 재사용/진행 중 조사 조회, 짧은 ID, 묶음 배정·효율 측정.
- **수정:** 기존 graph 저장/문서 생성·파일 영향 분석·문맥 조회·검증 재사용·Queue/진행 제어를 위 계약으로 확장한다.
- **축소:** 매번 전체 graph·문서·대화·로그를 AI에 전달하는 흐름과 같은 원리의 중복 탐색. 원문·근거의 보존은 기존 정책을 따른다.
- **goal:** 같은 요구·완료 기준에서 필요한 문맥과 변경분으로 작업하고, 품질을 유지하면서 입출력·호출·재작업 비용의 감소를 측정한다.
- **non-goal:** 새 graph 서버, 직접 모델 API, 원격 코딩 실행기, 의미 판단을 대신하는 템플릿, 검증 생략, 모든 작은 작업의 강제 graph 분해.

## 정형 입력·출력

AI는 작업 종류에 필요한 항목과 실제 변경분만 작성한다. Python은 ID·기본값·상속값·버전·반복 서식을 처리한다. 아래는 직접 운영 값이 아닌 필드의 의미다.

| 입력 | 의미·제약 |
|---|---|
| 대상·기준 | project/repository·노드 종류·현재 기준 commit/graph revision·요구/계획 버전 |
| 변경 의도 | 생성/갱신/관계 연결·해제/폐기, 변경 이유·근거; 삭제는 명시적으로 표현 |
| 내용 | 요약·대전제 또는 방법·의미 I/O·goal/non-goal·완료 기준·Test/로그·제품 범위·자율 범위 중 해당 종류의 필수 항목 |
| 관계 | 부모, 해결할 요구, 선행 의존, 공유 계약, 검증 근거의 고정 대상 ID 또는 유효한 짧은 참조 |
| 실행 조건 | 점유·권한·기대 버전, 역할/Step·조회 예산·필요한 상세 수준 |

| 출력 | 의미·제약 |
|---|---|
| 변경 결과 | 자동 발급 ID·새 버전·변경 노드/관계·원본/근거 참조 |
| 영향 결과 | 문서 구간·Step·검증 후보, 관계 경로·이유·확정/미확인 여부 |
| 문맥 결과 | 필수 문맥·관련 참조·재개 요약, 생략 항목·추가 조회 cursor·묶음 버전 |
| 오류 | 대상 노드/필드·실패 규칙·필요한 보정 값의 의미; 전체 데이터 재제출을 요구하지 않음 |
| 생성 결과 | 바뀐 문서 구간·원본/템플릿 hash·게시/복구 상태; 모델이 작성할 서식 본문을 반환하지 않음 |

노드 종류별 필수 항목을 구별한다. 생성 시만 기본값/상속을 적용하며, 갱신에서 생략한 값은 유지한다. 값 비우기는 명시적 clear로 처리한다. 긴 UUID는 Python이 발급하고 AI에는 짧은 ID를 제공할 수 있지만, 매핑 ID·project·graph 버전이 다르면 재조회한다. 저장소의 고정 UUID를 짧은 ID로 교체하지 않는다.

## 하나의 데이터셋과 부분 생성

- 자연어/구현 트리는 node의 종류와 parent/refines 관계로 표시한다. 연관 graph는 같은 node에 implements/depends_on/evidence와 필요한 공유 계약 관계를 연결한다. 각 화면용 사본을 독립 편집하지 않는다.
- Git의 구조화 데이터셋이 정형 내용의 원본이다. 생성 Markdown·graph 시각화·SQLite 역참조/문서 의존 인덱스는 같은 기준에서 파생한다. 인덱스에는 원본 식별·버전·hash를 남겨 재구축한다.
- 각 문서 구간은 참조 node/필드와 템플릿 버전의 의존 목록을 가진다. 변경된 의미 필드·관계·템플릿을 기준으로 필요한 구간만 다시 만든다. 상속된 부모값 변경도 소비 구간에 전파한다.
- 수기 설명·기존 문서는 생성 구간과 구별해 보존한다. 수기 내용이 구조화 원본과 충돌하면 조정 대상으로 반환한다. Git에서 생성 구간을 직접 수정한 경우도 원본 변경으로 해석·확정하기 전 자동 덮어쓰지 않는다.
- 동일 입력/템플릿의 출력은 결정적으로 생성한다. 생성 시각 같은 값으로 무관한 문서까지 바뀌지 않게 한다. DB·Git/파일 게시 사이의 부분 실패는 journal·원본 hash·요청 ID로 재개한다.

## 관계별 영향 규칙

| 변경 | 영향 탐색·판정 |
|---|---|
| 제목·표현 | 해당 표시 구간 재생성. 의미·기준이 같으면 구현/검증을 자동 무효화하지 않음 |
| 대전제·범위·입출력 계약 | 하위 요구·해결 구현·의존 소비자·공유 계약 사용처를 따라 Step/문서/시험 검토 후보 계산 |
| 구현 방법 | 원 요구의 변경과 구별해 해당 구현 가지와 소비자 영향 판단 |
| 근거·시험 정의·환경 | 해당 근거를 소비하는 지식/검증의 적용성 재판정. 무관한 성공까지 삭제하지 않음 |
| 연결 누락·소유 불명·동적 의존 | 영향 없음이 아니라 미확인으로 표시하고 필요한 구간만 AI에 전달 |

관계 방향을 명시하고 의존 대상이 바뀌면 역방향 소비자를 조회한다. 방문 집합으로 중복 탐색을 막고, 순환 금지 관계와 허용된 상호 참조를 구별한다. 수정 위치의 매핑은 영향 조회용 정보이며 하위 지시를 파일별 수정 레시피로 바꾸지 않는다. 의미 영향이 불확실한 부분은 AI가 판단한다.

## 토큰 절약 동작

| 기능 | 처리 방식·연관 부분 |
|---|---|
| 작업별 문맥 | 최상위는 대전제·구조·불확실성, 상위는 요구/의존/판정, 하위는 Step의 목표·경계·의미 I/O·방법·필수 근거를 중심으로 구성 |
| 점진적 상세 조회 | 요약·ID·적용 조건을 먼저 반환하고 필요한 원문만 추가 조회. 예산을 넘으면 생략/누락을 표시하며 필수 기준을 조용히 자르지 않음 |
| 세션 재개 | 현재 기준·진행/미처리 결과·미해결/차단·다음 행동·필수 결정 참조를 보존. 새 세션에서 버전·점유·증거 유효성을 다시 확인 |
| 조사·검증 재사용 | 질문/정의 버전·대상·입력·환경·의존 조건으로 재사용 키 생성. 지식에는 적용/무효화 조건을 포함하고, 단순 문장 유사성으로 같은 조사라 단정하지 않음 |
| 중복 실행 방지 | 재사용 조회와 새 조사 점유를 원자적으로 조정. 진행 중이면 원 결과를 기다리고, 실패/변경/증거 손상 시 재평가. 표준 Node/Step/run ID로 추적 |
| 도구 출력 축약 | 성공은 요약·ID·판정·증거 참조, 실패는 관련 오류·로그 구간·다음 조치. 큰 원본은 기존 보존/정제 규칙에 맞춰 리소스로 제공 |
| 소작업 묶음 | 같은 모듈·계약·문맥을 공유하고 충돌하지 않는 Step만 함께 배정. Step별 결과/증거/상태는 유지하며 부분 실패가 전체 완료가 되지 않음 |
| 반복 제어 | Python이 Queue·polling·정해진 재시도·진행 스냅샷을 처리. 실제 변화·오류·판단 요청·완료만 메인 AI에 알림 |

60초 내 상태 갱신은 Python이 도구 화면/조회 응답에 제공한다. 같은 상태 확인마다 AI 턴을 새로 시작하지 않는다. 화면 자동 갱신을 지원하지 않는 제품은 조회/로컬 로그로 현재 관찰을 제공하고, 닫힌 세션의 자동 기상을 보장하지 않는다.

캐시는 역할·허용 범위·원본/템플릿 버전·근거 지문으로 구별한다. 짧은 ID·재개 요약·문맥 묶음의 만료는 원본 삭제와 다르다. 오래된 묶음으로 실행하지 않으며 필요한 최신 부분만 다시 읽는다. Step 지시 원문은 승인된 실행 전달에만 포함하고 관리툴/일반 조회에는 참조만 둔다.

## Host 연결

로컬 Python이 원본 Git과 작업 공간을 점유·검토하고 문서/graph를 생성한다. Host는 실행 상태·공유 점유·결과·근거와 버전에 묶인 파생 인덱스를 제공한다. 모델 선택·실행은 로컬에 남는다.

서버 조회에 필요한 기준 데이터는 승인된 원본 버전/hash의 읽기용 snapshot 또는 참조로 전달한다. Host가 같은 본문을 별도 편집하지 않는다. 서로 다른 commit/dirty 상태의 결과를 혼합하지 않으며 기준 확인이 안 되면 캐시 미적중/재검토로 반환한다. 원격 응답에도 context budget·cursor·생략 표시를 적용한다.

## 시험·측정·완료

| ID | 확인할 결과 |
|---|---|
| P3-INPUT | 변경분 적용·기본값/상속·명시 clear·짧은 ID 만료·revision 충돌·재전송이 원본/고정 ID를 훼손하지 않음 |
| P3-GRAPH | 두 트리와 연관 graph가 같은 node를 사용하며 관계 방향·역참조·상속 변화·순환·누락을 구별 |
| P3-RENDER | 부분 생성과 전체 생성의 내용이 같고, 무관 문서/수기 영역 보존·직접 편집 충돌·게시 중단 복구 확인 |
| P3-CONTEXT | 역할별 필수 정보·근거·금지 범위·미해결 보존, 작은 예산의 누락 표시/추가 조회, 세션 재개·캐시 무효화 |
| P3-REUSE | 독립 프로세스/다른 환경의 동시 조사에 단일 실행, 같은 조건 재사용·후속 실패/환경 변화/근거 손상 거부 |
| P3-CONTROL | 반복 관찰에 불필요한 AI 호출 없음, 60초 관찰·변화/판단 통지·실패 로그 축약·재시도/점유 규칙 유지 |
| P3-BATCH | 묶음/개별 실행의 완료 기준·Step별 결과 동일, 공유 범위 충돌·부분 실패·불필요한 문맥 증가 검출 |
| P3-HOST | 로컬/Host 동일 계약, 다른 commit/권한의 캐시 혼용 방지, 단절/재연결·파생 인덱스 재구축 |
| P3-MEASURE | 신규 계획·부분 변경·재개·병렬 조사·모호한 요구 사례에서 최적화 전후 품질과 총비용 비교 |

비교는 같은 기준 commit·요구·환경·모델/역할·검증 정의로 수행한다. 정상/실패/재시도·추가 질의·재개 요약 생성 비용을 모두 포함한다. 제공되는 경우 실제 입력/출력/캐시 토큰을 구분하고, 미제공은 미상으로 표시한다. 문자/byte 기반 추정값은 실측 토큰이나 실제 요금으로 표시하지 않는다.

측정 항목은 모델 호출 수, 문맥/도구 응답 크기, 반복 조회·재조사·재검증 수, 재시도·재질문 수, 총 완료 시간, 기준 충족/오판/누락이다. 로그에는 task/run·기준/묶음/매핑 버전·참조 ID, 선택/생략/캐시 적중·무효화 이유·규모/시간·근거만 남긴다. 전체 문맥·대화·비밀을 측정 로그에 복제하지 않는다.

완료는 기존 안전·완료 기준과 위 시험을 통과하고, 대표 작업에서 감소한 비용을 근거와 함께 확인한 상태다. 과도한 요약·복잡한 조회 때문에 재작업이 늘면 문맥 예산/묶음 정책을 조정한다. 측정 전 고정 절감률을 약속하지 않는다.

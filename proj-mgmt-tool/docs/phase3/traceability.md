# Phase 3 plan-to-test traceability

This index connects all 48 planned IDs in [verification.md](verification.md) to current pytest scenarios and the evidence tier they actually exercise. The ID meaning is summarized from the feature spec/plan; test results do not enlarge that meaning. `pass` means the stated assertion ran at the named tier, `partial` means a material clause is absent or only simulated, and `not_run` means no qualifying execution evidence exists. Fixture or loopback HTTP evidence never stands in for an installed product or remote Host.

The repaired 0.3.0 source snapshot and six local acceptance groups are recorded in `evidence/local-acceptance/repaired-source/`. The aggregate is preserved as inconclusive because two test files changed only by Root-confirmed trailing whitespace during execution; the separate reconciled receipt records a 21-test current-source rerun and AST/source-hash proof. This establishes local-tier acceptance only. Current source fingerprints are in [traceability-source-hashes.json](evidence/local-acceptance/repaired-source/traceability-source-hashes.json); aggregate and reconciliation are [f15-local-acceptance.json](evidence/local-acceptance/repaired-source/f15-local-acceptance.json) and [f15-reconciled-local-acceptance.json](evidence/local-acceptance/repaired-source/f15-reconciled-local-acceptance.json).

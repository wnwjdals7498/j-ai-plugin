# 3단계 상세 구현 계획

2026-10-02. `gpt-6-luna` 서브에이전트 3개가 영역별 계획을 병렬 작성하고 메인이 연결 규격·작업 순서·검증 관문을 통합했다. **계획 작성 결과이며 코드 구현 착수/시험 통과 기록이 아니다.**

범위는 [기능 목록·명세](README.md), 의미 계약은 [F0](contracts.md), 시험 정의는 [검증](verification.md)을 따른다. 직접 모델 API·원격 코딩 실행기는 제외한다. 문서/graph 최적화와 본체 통합을 로컬에서 먼저 확인한 뒤 Host 저장 연결로 확장한다.

## 읽고 배정할 문서

| 작업 | 상세 단계·관찰·인계 |
|---|---|
| F0 공통 연결·호환·초기 비교 기준 | 이 문서 + [구현 연결 규격](implementation-interfaces.md) |
| F1~F4 변경·조회·영향·부분 생성 | [데이터·문서 계획](plan-graph-document.md) |
| F5~F9 문맥·재사용·출력·제어·묶음 | [문맥·실행 계획](plan-context-execution.md) |
| F10 로컬 전체 통합·효율 판정 | 이 문서 + [측정 명세](spec-local-measurement.md) |
| F11~F15 서버·설정·이관·복구·배포 확인 | [Host·통합 계획](plan-host-integration.md) |

F번호-S번호는 문서의 논리 작업 ID다. 실제 PMT Step UUID는 착수 시 발급하고 연결한다. 각 단계는 기능 변경·필요 계약·처리/실패 복구·예정 시험/실제 관찰·인계를 구체화하며 파일별 수정 레시피는 만들지 않는다.

## F0 착수 단계 — 메인과 저장 담당

| Step | 작업·입력→산출물 | 완료·관찰·인계 |
|---|---|---|
| F0-S1 | 현재 schema 3/graph 1/protocol-v1·실측·미확인 목록과 명세를 비교해 재사용/확장/이관·source/runtime 경계 확정 | 기존 API·소유/기능 분리·지원 표. P3-F0-01, 자료/요청의 실제 호환을 기록 |
| F0-S2 | SourcePin/ChangeSet/Index/Manifest/Context/Reuse/Action/Binding의 의미·오류·로그/시험 registry 확정, 공통 저장 포트와 로컬 연결 구현 | 소비자가 다른 계약을 만들지 않음. P3-F0-02, 기존 로컬 호출과 포트의 envelope/충돌/replay 대조 |
| F0-S3 | 필요한 파생 index·문맥/alias·재사용 claim·제어/notice·group binding·측정 저장 경계와 호환 이관/rollback 구현·인계 | 공유 schema/transaction 담당 1명, 소비자는 함수를 사용. 기존 ID/claim/근거 보존·실패 중 원본 보호 |
| F0-S4 | 신규/변경/재개/조사/모호함/실패 사례를 같은 조건의 최적화 전 실행으로 고정하고 비교 manifest 보관 | P3-F0-03, 실제/미상/추정·모델/환경·정의/입력/결과 기준 분리. F10에 재현 기준 인계 |

F0-S1→F0-S2가 먼저다. F0-S3/F0-S4는 저장/비교 담당의 독립 범위에서 병렬 준비할 수 있다. 실제 F1/F7 코드 착수는 해당 소비자의 저장/계약/초기 기준 인계가 끝난 뒤다. Host connection 대역은 계약 준비용이고 실제 Host 통과가 아니다.

## F10 로컬 통합 단계 — 메인

| Step | 작업·입력→산출물 | 완료·관찰·인계 |
|---|---|---|
| F10-S1 | F4/F9와 실제 의존 서비스를 연결해 변경→문서/문맥→재사용/배정→결과 검토→재개 흐름 실행 | P3-F10-01, DB/Git/파일/handle·기준별 증거 일치. F2-F4 manifest, F8-F9 group 연결을 실제로 확인 |
| F10-S2 | F0 기준과 동일 요구/환경/모델/정의로 최적화 흐름 비교, 질의·요약 생성·실패/재시도/재검토까지 집계 | P3-F10-02, 토큰 미상/byte 추정과 실제 usage 구분·품질 누락·비교 불가 사유 보존 |
| F10-S3 | 비용 증가/문맥 부족/오류 전파의 원인을 해당 기능 소유자와 수정하고 영향 시험만 다시 수행 | P3-F10-03, 실제 개선/한계·정책 선택·미해결. 검토된 저장/API 계약을 F11에 인계 |

F10-S1→F10-S2→F10-S3 순이다. 의미 품질은 실제 사용할 수 있는 native 모델로 별도 관찰하고, 제품 CLI는 승인된 로컬 fixture로 전달 경계를 확인한다. 미설치/필수 권한 부족은 blocked, 토큰 usage 미제공은 미상으로 기록한다. 기존 2단계 통과 수를 신규 시험 성공으로 합치지 않는다.

## 구현 배정 순서

| 순서/관문 | 작업 배정 | 다음 착수 조건 |
|---|---|---|
| G0 공통 기반 | 메인 F0-S1/S2, 저장 담당 F0-S3, 비교 담당 F0-S4 | 실제 계약·저장/호환·초기 기준 인계 |
| G1 변경/조회/영향 | F1→F2→F3 순차; F7은 G0 뒤 독립 병렬 | canonical ID/source/index·영향 known/unknown, 실제 연계 시험 |
| G2 로컬 독립 기능 | F4 / F5 / F6를 `gpt-6-luna` 3명 병렬 | 담당 자체/계약 시험·소비자 인계; 미완성 소비를 통과로 표시하지 않음 |
| G3 제어·묶음·통합 | F5/F6/F7 인계 후 F8, 이후 F9; F4 완료 후 F10 연결 | 로컬 전체 기능·실제 근거·측정/품질 판정 |
| G4 저장 서버 | F11 | 실제 저장/인증/호환/동시성 경계 확인 |
| G5 연결·이관·복구 | F12 / F13 병렬, 두 기능 인계 후 F14 | shared namespace·ID/근거·단절/재개·소유/버전 조정 |
| G6 최종 수용 | F15 단계별 실제 제품/환경·배포/업데이트·전체 효율 확인 | 필수 시험·실측·미해결과 완료 범위를 메인이 판정 |

직접 선행이 끝나면 준비된 작업을 먼저 배정할 수 있다. 모델 작업자는 실제 실행 한도 내 최대 3개, 같은 에이전트의 지정 모델/도구/권한을 지원하면 native subagent 우선이다. source/model 호출 상태가 불명확한 작업을 다른 경로에 중복 배정하지 않는다.

## 소유·공유 변경 규칙

- 메인은 기능 범위·공통 타입/오류·공개 CLI/서비스/HTTP 노출 정책·시험/로그 registry·통합·최종 판정·Git을 소유한다.
- 저장 담당은 실제 schema/이관/공통 transaction·원자 claim·group binding·기초 index 저장 경계를 소유한다. F1~F15 담당이 공유 DB 구조를 각각 수정하지 않는다.
- F1 변경/F2 조회/F3 영향은 순차 인계, F4 renderer/F5 context/F6 reuse는 독립 소유. F7 output/F8 control/F9 batch는 각 서비스 책임을 유지한다.
- F11은 서버 저장/auth/HTTP만 소유하며 Git/working tree/문서 생성·runner 실행은 원격 allowlist에서 제외한다. F12는 클라이언트 설정/매핑, F13은 이관/복원 coordinator, F14는 outbox/재조정이다.
- 실제 변경 영역·공유 경계·필요 worktree는 작업자가 착수 시 제안하고 메인이 지정한다. 별도 checkout도 공통 계약 충돌을 해결해 주지는 않으므로 통합·공유 자료 게시를 직렬화한다.
- 자체 시험은 해당 담당이, 실제 소비자 연결/환경 시험은 통합 관문에서 수행한다. 한 구현 영역을 두 작업자에게 동시 수정·검증하도록 배정하지 않는다.

## 지시·반환·판단 기준

메인은 논리 Step ID와 기능/명세/연결 계약 버전, 목적·goal/non-goal, 추가/수정/삭제 기능·소유/금지 범위, 의미 I/O·필수 source/context refs, 방법/기술·선행 인계, 기존 P3 시험 ID·로그/증거·완료/자율 경계를 전달한다. 관련 문서만 읽게 하고 전체 명세를 매번 복제하지 않는다.

반환에는 실제 변경 영역·계약 버전·criterion별 pass/fail/blocked/not_run, 실제 모델/경로·명령/action/exit·환경/commit/dirty·증거 ref, 계약 변경 제안·미해결·다음 조치를 담는다. Task/run·source/hash·논리 Step/시험 ID로 trace를 연결한다.

노드/템플릿 표현·일관된 내부 자료구조·조건 내 backoff/조회 예산은 작업자 자율이다. 사용자 목표·대전제·원본/권한·공개 계약/호환·소유 범위·검증 기준 변경은 근거와 영향을 메인에게 제시한다. 실제 운영 주소·기기/credential·배포 위치는 구현 중 확인하며 미정 값을 임의로 채워 배포하지 않는다.

직접 모델 API·기존 사용자 설정/운영 DB 변경·Claude 실서비스로 시험정보 전송은 이 계획의 자동 실행 대상이 아니다. 사용자가 지정한 네이티브 서브에이전트 배정은 유지한다. 실제 배포/전환은 이미 허용된 범위·확인된 운영값/권한을 따른다. 접근이 없어 실행 못한 필수 항목은 그대로 남기고 계획/fixture를 전체 성공으로 바꾸지 않는다.

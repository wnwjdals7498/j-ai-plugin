The new Host `publish_client_plan` operation accepts only an explicit approval request bound to the active Project run, current SourcePin, completed F4 document-effect revision, registered segment manifests, and a complete F4 coverage certificate. It validates the immutable graph resource and current F2 index, then writes a published row referencing the existing graph resource. A separate stable plan hash and `client_plan_receipt` retain source, effect, coverage, and manifest-set references without copying graph/document bodies. Same-ID replay, body conflict, stale SourcePin, changed effect revision, incomplete coverage, and active old-plan consumers are rejected. `read_client_plan` returns scoped metadata and artifact refs only. Hosted Step authorization now checks the selected published Plan against the current workspace, graph artifact, graph hash/version, and baseline commit.

`ClientRoutingConfig` stores the existing Phase 2 policy/capability schema in `ConfigRoot/routing-client.sqlite3`, reuses the routing service validator/selector, and records semantic request replay locally. The hosted CLI selector routes these five operations to this ConfigRoot port before Host operation selection; the routing request scope remains in the semantic fingerprint but is not recorded as a local business event. It does not open the business store or contact Host. An optional one-time migration reads legacy `pmt.sqlite3` routing rows read-only, preserves policy preferences and revisions, downgrades environment-specific capabilities/auth observations to unknown, records the imported source fingerprint and disabled API policy, and leaves legacy bytes unchanged. `route_for_enqueue` strips selection-only fields so only the existing bounded route identity reaches Host.

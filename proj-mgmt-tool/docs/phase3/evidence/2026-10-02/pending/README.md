`pmt.pending.PendingOutbox` is a namespace/actor/device/environment/session-bound local SQLite spool. It accepts only `submit_execution_result`, `record_verification`, and `record_reuse_result`; claims, new work, shared changes, review, finish, release, and cancel operations are rejected. `preflight_new_shared_write(store, operation, scope_id=..., permission=...)` requires an authenticated compatible Host with the exact selected scope and permission for a new shared write; it fails closed when the Host is unavailable.

`enqueue_result(...)` requires an explicit or request-bound run ID and the versioned local HostedRuntime receipt, its raw manifest/receipt/output bytes, the terminal physical-stop bit, owner, source, and attached revision. It stores the normalized result’s body hash and semantic request fingerprint. A sensitive `actual_route` is replaced in the outbox by a run-bound marker; after reconnect, the current authorized run read supplies the route and the complete request must reproduce both original hashes before lookup or replay. Unsafe route values remain `pending_incomplete`; they are never written into the outbox. Secret-like fields, environment variables, local paths, claim tokens, credentials, and unbounded content are refused.

`stage_resource(...)` takes bytes only from a caller-supplied reader of an already-created local output, stores them content-addressed with a hash, and holds a separate original upload UUID. `publish_staged_resource(...)` requires current identity, scope, SourcePin, and authorization facts; after an uncertain upload it retries the exact body and original upload ID. `reconcile(...)` requires actual versioned auth/scope/SourcePin/run-read facts, checks the original request result, and only then replays the exact original request ID/body. It never creates a replacement owner, request ID, or shared claim.

Current-facts callbacks return `pmt-pending-current-facts-v1`, containing the current `SourcePin`, a hash-bound Host authorization profile, and a hash-bound run read including its actual route. These are adapter inputs from authenticated Host/F5 reads, not caller Boolean flags. Outcome states are `pending`, `pending_incomplete`, `unknown`, `applied`, `already_applied`, `conflict`, and `stale`; resource states include `staged`, `unknown`, `published`, `pending_incomplete`, `conflict`, and `stale`. Pending rows are checksum-checked and immutable; state transitions use short SQLite compare-and-set transactions. A crash during checking/upload restarts as `unknown`, never as permission to launch or claim work.

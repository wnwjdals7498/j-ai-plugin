# F12 storage selector evidence

The existing protocol-v1 `pmt` stdin/stdout path is unchanged. With no `storage.json` or an explicit `local` profile, the CLI selects `LocalStore`. A `hosted` profile selects `HttpStore` for the Host application/data allowlists, checks compatibility and registers the actual request session. It never instantiates the local business database as a fallback. Unsupported client-local filesystem, Git, document and runner operations return an explicit unavailable/forbidden result until their runtime adapter is connected.

`pmt storage configure`, `probe`, and `status` use bounded JSON input/output. Configure probes TLS, compatibility, principal and a deterministic environment setup session before writing `storage.json` with expected-hash CAS. The file stores only the credential environment-variable name. Workspace mappings keep absolute checkout paths in ConfigRoot; outbound Host requests receive canonical workspace IDs, project/repository IDs and relative graph paths. Hosted hook events are bound to the compatibility actor only for normalized native `record_event` envelopes, preserve native session/event/request IDs, and require `PMT_SCOPE_ID` matching a configured project mapping.

The local F12 suite passed 10 tests, including actual loopback HTTPS setup, two local mappings/scopes, canonical path adaptation, cross-scope denial, actor mismatch, hook provenance, and no local SQLite fallback. The existing local hook suite passed 34 tests. The actual workspace resolver and existing HttpStore/TLS contracts were exercised; the hosted local Git/runner adapter is still explicitly unsupported until its remote control-state RPC is available. No installed native-product or external model calls were made.

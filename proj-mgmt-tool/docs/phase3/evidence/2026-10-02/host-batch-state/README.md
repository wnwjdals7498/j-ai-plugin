# Host F9 batch-state evidence

The Host DataExtension now routes `prepare_step_batch`, `bind_step_batch`, and `collect_step_batch` into the existing Core F9 file operation. It also exposes `read_step_batch` as an owner-bound metadata read. Host prepare accepts only canonical `pmt://` workspace identities and existing run references; Core F9 still acquires the union claim and performs F5 source/context checks. The Host does not read a client checkout or execute a runner.

`read_step_batch` requires the current runtime principal, owner session, parent run revision, project scope, and unchanged Host SourcePin. It verifies current member Steps, F5 context refs, directive version/hash, criteria hashes, and group locks, then returns bounded refs and metadata. It does not return directive bodies, prompts, local paths, arguments, process IDs, or environment values. Incomplete contexts return `execution_enabled=false` with missing-section reasons.

The actual in-process Host test seeded two queued P2 Steps in one isolated SQLite database, published their graph snapshot to Host resources, and invoked Core F9 through HostApplication/DataExtension. It verified current F5 projections for both Steps, attached one real persisted P2 handle record and exercised the F9 bind hook, submitted a hash-bound structured report, and collected two child F7/P2 results. It also confirmed local `read_step_batch` fails with `host_connection_required`, a different actor cannot read the binding, and a changed parent report hash is rejected before recollection. The fixture did not call an external model or start a product runner.

The focused Host data + two-Step Host batch + existing LocalStore F9 prepare regressions passed. An additional whole F5 context-suite run produced 16 passes and one Windows fixture setup error (`attempt to write a readonly database`) while `actual_context_env` was creating its initial evidence resource; that failed before the affected test body ran. No HTTP transport, installed product, external model, Linux host, or deployment behavior is claimed here.

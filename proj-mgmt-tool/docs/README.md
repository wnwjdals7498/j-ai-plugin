# PMT v3 구현 계획

- 작성일: 2026-09-30
- 상세계획 갱신: 2026-10-01
- 상태: [1단계 구현·검증 완료](phase1/implementation-status.md). 2단계 두 요구 트리·역할·Step 계층·태그 규격 합의 반영, 구현 전. 3단계는 설계 계획.
- 목적: 회사·집·노트북과 여러 AI 세션에서 작업 상태·결정·근거를 공유하고, 중복 작업과 검증을 줄인다.

## 구현 순서

| 단계 | 완성할 기능 | PMT 저장 위치 |
|---|---|---|
| [1. 로컬 기록](01-local-storage.md) | 구현 → 본체 검증 → 플러그인화 → 설치 검증 | 로컬 SQLite |
| [2. 모델 분배](02-model-routing.md) | 자연어 요구 트리 → 구현 요구 트리·기능 명세 → Step 지시 → 병렬 실행·제품 단계별 판정 | 1단계 저장소 + 내부 지시 리소스 |
| [3. 서버 연결](03-hosted-storage.md) | 저장 API·플러그인 setup·환경 간 공유 | 로컬 또는 Host SQLite |

각 단계의 완료 기준을 실제로 확인한 뒤 다음 단계로 진행한다. 2단계까지는 PMT 서버 없이 사용할 수 있어야 한다. 3단계에서도 모델 분배·코드 실행은 각 작업 환경에 유지한다.

1단계 구현은 [AGENTS.md](../AGENTS.md)와 [상세 작업 안내](phase1/README.md)를 기준으로 한다. `gpt-6-luna` 병렬 작업의 입력·출력·기술·의존 관계, 필수 시험 ID, 로그·증거, 제품별 설치 완료 기준을 연결했다. 상세계획은 파일별 수정 목록 대신 기능 책임과 관찰 가능한 결과를 정의한다.

## 공통 원칙

- 작업 상태·결정·이력·점유·실행 메타데이터는 SQLite가 원본이다. 저장소의 장기 구조·개발·운영 규칙은 Git 문서를 원본으로 참조한다. Step 지시는 내부 리소스 한 곳에 보관하고 SQLite는 버전·hash·참조를 관리한다. 같은 본문을 여러 원본에서 각각 수정하지 않는다.
- 같은 내용은 한 번 저장하고 고정 ID로 연결한다. 긴 이미지·로그·증거는 `resources`에 둔다.
- 최신 작업 상태와 의미 있는 변경 이력을 구분한다. 단순 heartbeat는 이력으로 쌓지 않는다.
- 응답 종료, 프로세스 종료, 작업 완료는 구분한다. 완료는 기준과 결과·검증 근거를 확인한 후 확정한다.
- 같은 코딩 에이전트에서 대상 모델·도구·권한을 지원하면 **서브에이전트를 우선** 사용한다. 사용자가 명시한 실행 방식은 우선한다.
- 상위 모델이 기본 메인을 맡아 결과를 취합·판단한다. 최상위는 필요한 구조·큰 기준 판단에 참여하고 하위는 확정 Step의 결과·증거를 반환한다. Work/Item은 목표·요구, Step은 실행 단위다.
- 자연어 요구는 분리할 때마다 대전제를 기록하고, 구현 요구는 원 요구·대전제를 참조한다. prototype·기능 확장·production의 제품 범위와 확인 기준은 PMT 개발 단계·작업 상태·태그와 구별한다.
- 원리·검증 결과는 현재 상황에 적용되는지 확인한 후 재사용한다. 모델의 설명이나 확신만으로 검증 성공을 기록하지 않는다.

## 처음부터 유지할 경계

| 경계 | 최소 기능 | 다음 단계에서 유지할 것 |
|---|---|---|
| 저장 연결부 | `read_context`, `save_change`, `claim_task`, `finish_task` | 3단계에서 `LocalStore`를 `HttpStore`로 교체 가능 |
| 실행 연결부 | `start`, `status`, `result`, `cancel` | 서브에이전트·CLI/SDK·직접 API의 공통 입출력 |
| 데이터 | 고정 ID·revision·출처·증거 참조 | 경로·환경·실행 제품이 바뀌어도 관계 유지 |
| 실행 이력 | 작업 ID와 실행 시도 ID 분리 | 재시도·실패·부분 결과를 별도 추적 |

## 보존과 동기화

| 데이터 | 보존 기준 |
|---|---|
| 일반 실행·진행 이력 | 종료 후 3개월 |
| 미참조 임시 handoff·테스트 이미지 | 생성 후 1주일 |
| 현재 요구사항·결정·유효 지식·참조 증거 | 유효한 동안 |
| 진행 작업·미처리 결과 | 처리·정리 전까지 보존 |

임시 파일이 확정 근거가 되면 정식 리소스로 전환한다. 증거를 강제로 삭제하면 해당 검증의 재사용 자격도 만료한다. 정리 기능은 기본 읽기·쓰기가 안정된 뒤 붙인다.

외부 프로젝트 관리 도구 연동은 후속 기능이다. 도입 시 Project·Work 요약과 결정·파기를 대상으로 하고, Item·내부 공통문서·증거 파일은 PMT 내부에 유지한다. 하위 모델용 Step 지시 원문은 관리툴에 포함하지 않으며 필요한 식별자·상태·참조·결과만 관리한다.

원격 실행기 자동 배정, 서버발 Callback 푸시, 메시지 브로커, 오프라인 양방향 동기화는 현재 3단계의 필수 범위에 포함하지 않는다.

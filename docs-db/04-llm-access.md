# 04. 에이전트 접근 — 적은 토큰으로 읽고 쓰기

출처: 원문 `docdb-token-spec.md`. 2026-10-13 변경점은 6~7절.

## 1. 전제

DB에 저장된 양은 토큰과 관계없다. 토큰은 한 요청에 실리는 것(도구 정의, 지침, 도구 결과, 대화 이력)과 모델이 쓰는 출력에서 생긴다. 그래서 원칙은 **"저장은 세밀하게, 싣는 것은 최소로"**다.

| # | 토큰이 드는 곳 | 성격 | 대응 |
|---|---|---|---|
| T1 | 도구 정의·서버 지침 | 매 요청 고정 비용 | 도구 6개, 짧은 설명 |
| T2 | 도구 결과 | 한 번 실리면 이후 매 턴 다시 전송 | 예산, 단계적 공개, 변경분만 |
| T3 | 모델 출력 | 입력보다 단가가 높음 | 패치로 쓰기 |
| T4 | 실패·재시도 | 오류+재독+재작성 | 원자적 쓰기, 짧은 오류 코드 |

## 2. 원칙 (TOK-P1~P7)

| ID | 원칙 |
|---|---|
| P1 | 저장은 세밀하게, 싣는 것은 최소로 |
| P2 | 조인·집계·필터는 SQL이 하고 모델은 결과만 받는다 |
| P3 | 단계적 공개: L0(한 줄) → L1(요약) → L2(필드 전문) |
| P4 | 바뀐 것만 다시 보낸다(커서 `as_of=c:N`, digest) |
| P5 | 출력은 패치로. 쓰기 응답은 본문을 되돌려주지 않는다 |
| P6 | 모든 응답에 예산을 두고, 자른 수는 `omitted=N`으로 알린다 |
| P7 | 고정 비용을 작고 일정하게. 도구 목록을 상태에 따라 바꾸지 않는다 |

## 3. 핸들과 공개 단계

| 핸들 | 대상 | 예 |
|---|---|---|
| `d:` | 문서 | `d:DOC-REQ-HWCHECK` |
| `f:` | 필드(문서/종류/필드) | `f:DOC-REQ-HWCHECK/D01/behavior` |
| `i:` | 항목 | `i:REQ-HW-001` |
| `w:` `r:` | 작업, 실행 | `w:WORK-2026-0001`, `r:RUN-0002` |
| `k:` | 문서 종류 | `k:D01` |

| 단계 | 내용 | 크기 |
|---|---|---|
| L0 | 핸들·상태·제목·`dg`(digest 앞 16자리)·`tok` 한 줄 | 15~40 tok |
| L1 | L0 + 최신 요약 | 60~100 tok |
| L2 | 필드 전문(`f:` 핸들만) | `tok` 값만큼 |

문서(`d:`) 핸들로는 전문을 주지 않는다. 문서 하나를 통째로 싣는 경로를 없애기 위해서다.

## 4. MCP 도구 6개

| 도구 | 입력 | 출력 | 기본 예산 |
|---|---|---|---:|
| `docdb_ctx` | work_id | 작업 카드·다음 행동·차단 요인·관련 문서 L0·항목 개수·필드 L1. 읽은 대상은 `context_read`에 자동 기록 | 1,500 |
| `docdb_get` | handles, level, known{h:dg} | 핸들별 L0/L1/L2. `known`이 같으면 `UNCHANGED` | 2,000 |
| `docdb_find` | query | 핸들+짧은 발췌. 3글자 이상은 전문 검색, 미만은 `LIKE` | 800 |
| `docdb_trace` | handle, rel, depth | `a -rel-> b` 간선(ID만) | 800 |
| `docdb_since` | cursor | 바뀐 대상별 1줄 + diff 최대 6줄 | 1,200 |
| `docdb_put` | patches | `APPLIED/NOTHING_APPLIED` + 핸들별 `OK dg tok` 또는 `ERR 코드` | — |

노출하지 않는 기능: 승인, 카탈로그 변경, legal_hold 해제, 관계 확정·삭제. 사람이 CLI로만 한다. AI 승인은 트리거로도 막는다.

## 5. 표준 호출 순서

| 단계 | 호출 | 다음 판단 |
|---|---|---|
| ① 시작·재개 | `docdb_ctx(w)` | 무엇을 더 볼지 |
| ② 좁히기 | `docdb_get(level=1)` / `find` / `trace` | 고칠 필드 결정 |
| ③ 상세 | `docdb_get([f:...], level=2)` | 패치 작성 |
| ④ 쓰기 | `docdb_put([...expect: dg])` | 끝(다시 읽지 않음) |
| ⑤ 다음 세션 | `docdb_since(c:N)` | ①로 |

하지 말 것: 문서 전체를 읽고 필드 하나에 답하기, 쓰고 나서 확인하려고 다시 읽기, 같은 필드를 다시 전문으로 읽기(`known` 사용), 목록 두 개를 받아 모델이 맞춰 보기(`trace`·뷰 사용), 범용 SQL 도구.

## 6. 변경점 1 — 외부 전송 정책 필터 (D8)

`document.export_policy`가 `local_only`인 문서는 에이전트 응답에 본문을 싣지 않는다.

| 도구 | `local_only` 문서 처리 |
|---|---|
| `get` L1·L2 | 핸들·제목·`dg`·`tok`만, `policy=local_only` 표시 |
| `ctx` 필드 L1 | 요약 대신 `policy=local_only` |
| `find` | 일치한 핸들만, 발췌 없음 |
| `since` | diff 대신 변경 사실과 글자 수만 |

import로 들어온 문서의 기본값은 `approved_providers`다(2026-10-13 사용자 확인: 외부 전송 가능).

## 7. 변경점 2 — `put` 확장 (D10)

`i:` 핸들(`upsert`)과 관계 연산(`link`·`unlink`)을 추가한다. 형식과 규칙은 [03-relations.md](03-relations.md) 3.2절.

오류 코드(짧게, 고칠 방법 포함): `CONFLICT now=<dg>` · `ANCHOR_NOT_FOUND` · `UNSUPPORTED_HANDLE` · `BAD_OP` · `NEEDS_HUMAN` · `REJECTED_BEFORE rel=<id>` · `DB <제약 메시지>`.

## 8. 측정 효과

`test_token.py` 합성 데이터 기준. 2026-10-13 재실행으로 같은 값 확인. 토큰 수는 보정 전 추정치(ASCII 3.5자=1 tok, 그 외 1자=1 tok)라 비율만 의미가 있다.

| 상황 | 기존 방식 | 이 방식 | 비율 |
|---|---|---|---:|
| 작업 시작 | 원시 덤프 20,031 tok | `ctx` 1,467 tok | 7.3% |
| 재개 | 필드 전체 재독 8,579 tok | `since` 116 tok | 1.4% |
| 같은 필드 재조회 | 413 tok | `UNCHANGED` 21 tok | 5.1% |
| 일부 수정(모델 출력) | 318 tok | 패치 58 tok | 18% |
| 항목 40개 목록 | JSON 2,062 tok | 한 줄 형식 1,466 tok | 71% |

## 9. 연결 설정 원칙

| 대상 | 설정 |
|---|---|
| Claude Code | 도구 검색 기본값 유지(도구 정의는 필요할 때만 실림), `alwaysLoad` 끄기, 결과는 1만 tok 이하 |
| Codex | `enabled_tools`로 6개만 허용, `tools.<tool>.output_token_limit`으로 결과 상한 |
| 공통 | 도구 목록·설명을 자주 바꾸지 않는다(캐시 무효화 방지) |

셸이 있는 에이전트는 같은 기능을 CLI(`docctl ctx|get|find|trace|since|put`)로도 쓸 수 있다.

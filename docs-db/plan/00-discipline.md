# 00. 실행 규율

구현자(Sonnet 서브에이전트)와 리뷰어가 **매 작업마다** 지키는 규칙이다. 이 문서, [01-contracts.md](01-contracts.md), 맡은 작업([02-tasks.md](02-tasks.md)의 해당 절)을 먼저 읽고 시작한다.

## 1. 역할

| 역할 | 누가 | 하는 일 | 하지 않는 일 |
|---|---|---|---|
| 오케스트레이터 | 메인 세션(Claude) | 작업 배정, 실측(T00a~T00c), 결정 확인, 결정 문서·계약 갱신, PMT 기록, 병합, 사용자 보고 | 구현자 대신 코드를 크게 고치기 |
| 구현자 | Sonnet 서브에이전트(작업당 새로 시작) | 맡은 작업 **하나**를 TDD로 구현하고 커밋 | 다른 작업 범위 손대기, 계약·결정 문서 수정, push |
| 리뷰어 | 새 서브에이전트 | [03-review.md](03-review.md) 체크리스트로 판정 | 직접 고치기(지적만) |

## 2. 문서 우선순위

충돌하면 위의 것을 따른다.

1. [01-contracts.md](01-contracts.md) — 이름·형식·알고리즘
2. [02-tasks.md](02-tasks.md)의 해당 작업 — 범위·수용 테스트
3. [../09-decisions.md](../09-decisions.md) — 결정
4. `docs-db/01~12` 문서 — 설명
5. `docs-db/reference/docdb-package/` — 원본 코드·SQL(이식 대상)

같은 순위 안에서 충돌하거나, 필요한 내용이 어디에도 없으면 **추측하지 않고 멈춘다**(7절).

## 3. 절대 금지

1. 계약(C-xx)에 없는 이름을 새로 만들지 않는다: 모듈, 공개 함수, 함수 인자, 오류 코드, 환경 변수, CLI 명령·옵션, 출력 줄 형식, 테이블·컬럼. 비공개 도우미 함수(`_`로 시작)는 만들어도 된다.
2. 작업의 "대상 파일" 밖의 파일을 만들거나 고치지 않는다.
3. 의존성을 추가하지 않는다. 런타임은 `pysqlite3`, `mcp`, 개발은 `pytest`뿐이다(C-02).
4. `pysqlite3`는 `db.py`에서만, `mcp`는 `mcp_server.py`에서만 import한다. 표준 `sqlite3` 모듈은 어디서도 import하지 않는다(C-01).
5. Python 3.11 이상 전용 기능을 쓰지 않는다(C-02 목록).
6. 네트워크 호출을 넣지 않는다(`setup`의 pip 호출 제외). 테스트도 네트워크 없이 통과해야 한다.
7. 커밋된 마이그레이션 파일, `docs-db/reference/`, `docs-db`의 결정·설계 문서를 고치지 않는다.
8. 테스트를 약화하지 않는다: 단정 삭제·완화, `skip`·`xfail` 추가, 기대값을 구현 결과에 맞춰 바꾸기 금지. 원본 이식 테스트의 기대 수치는 계약이 명시한 경우만 바꾼다(C-27).
9. 오류를 숨기지 않는다: 빈 `except`, `except Exception: pass`, 실패를 성공으로 바꾸는 대체값 금지. 잡은 예외는 `DocdbError`로 바꿔 다시 던진다.
10. SQL에 값을 문자열로 끼워 넣지 않는다. 값은 항상 `?` 매개변수. 테이블·컬럼 이름을 동적으로 넣을 때는 코드에 고정된 허용 목록에서만 고른다.
11. MCP 서버 경로에서 stdout에 쓰지 않는다(`print` 금지). 로그는 stderr.
12. 비밀 값(실제 키·토큰)을 코드·테스트·커밋 메시지에 넣지 않는다. 민감 정보 테스트에는 형식만 맞춘 가짜 값을 쓴다(예: `"AKIA" + "A" * 16`).
13. `git push`, 원격 작업, 브랜치 삭제, `git reset --hard`, 자동 stash를 하지 않는다.
14. `datetime.now()`를 직접 부르지 않는다. 시각은 `clock.now_iso()`(C-07).

## 4. 반드시 지킬 것

1. **TDD 순서**(5절)를 지킨다. 테스트 없이 구현을 먼저 쓰지 않는다.
2. 모든 쓰기는 `db.write_tx` 안에서 한다(C-08).
3. `RECORDED_TABLES`의 모든 생성·수정·삭제는 같은 트랜잭션에서 `history.append_change`로 기록한다(C-15).
4. 모든 자유 텍스트는 `textnorm.normalize_text` 후 저장하고, digest는 `textnorm.digest16`으로 계산한다(C-06).
5. 자유 텍스트를 쓰기 전에 `policy.assert_no_secrets`를 호출한다(C-16).
6. 파일은 `pathlib.Path`로 다루고 텍스트 파일은 `encoding="utf-8"`로 연다.
7. 공개 함수에는 타입 표기와 한국어 docstring(1~3줄)을 단다.
8. 오류는 `DocdbError(code, detail)`로만 올린다. 출력 형식으로 바꾸는 것은 CLI·MCP 경계에서만 한다.
9. ID는 `ids.validate`·`ids.next_id`로만 검사·발급한다(C-10).
10. 사람 전용 동작은 `actors.require_human(actor, interactive)`로 막는다(C-11).

## 5. 작업 절차

각 작업은 아래 순서로 진행한다. 순서를 바꾸거나 건너뛰지 않는다.

1. **읽기**: 이 문서, 작업 절, 작업이 참조하는 계약 절(C-xx), 작업이 참조하는 결정·문서 절을 읽는다. 이식 작업이면 원본 파일도 읽는다.
2. **확인**: 작업의 "선행 작업"이 커밋되어 있는지 `git log --oneline`으로 확인한다. 없으면 멈춘다.
3. **테스트 작성**: 작업의 "수용 테스트" 표의 **모든 행**을 테스트 함수로 만든다. 테스트 함수 이름은 `test_<작업ID 소문자>_<행 번호>_<짧은 설명>`(예: `test_t02_3_crlf_digest_same`). 표에 없는 테스트를 더해도 되지만 표의 행을 빼면 안 된다.
4. **실패 확인**: 새 테스트만 실행해 실패하는 것을 본다. 실패 이유가 "구현 없음"이 아니면(예: 픽스처 오류) 테스트를 먼저 고친다.
5. **구현**: 계약을 지키며 테스트를 통과시키는 최소 구현을 쓴다. 작업 범위 밖 기능을 미리 만들지 않는다.
6. **작업 테스트 통과**: 새 테스트가 모두 통과하는지 본다.
7. **전체 테스트 통과**: `cd docdb && .venv/bin/python -m pytest` 전체를 실행한다. 이전 작업 테스트가 깨지면 고친다(테스트를 고치는 것이 아니라 구현을 고친다).
8. **자체 점검**: [03-review.md](03-review.md) 1절 공통 체크리스트를 스스로 확인한다.
9. **커밋**: 작업당 커밋 하나(9절 형식). 대상 파일만 `git add`한다(`git add -A` 금지).
10. **완료 보고**: 8절 형식으로 보고한다.

## 6. 판단 규칙

계약이 정하지 않은 세부를 정해야 할 때 아래 순서로 판단한다.

1. 원본 코드(`reference/`)에 같은 동작이 있으면 원본을 따른다.
2. 결정 문서에 B·C 등급 미결로 남은 항목이면 10절의 기본 동작을 따른다.
3. 위 둘에 없고, 선택이 **외부에 보이는 동작**(출력, 오류 코드, 저장 값, 파일 경로, 인자)을 바꾸면 멈추고 보고한다.
4. 외부에 보이지 않는 내부 구현(비공개 함수 분리, 지역 변수 이름, 반복문 형태)은 구현자가 정하되, 가장 단순한 방법을 고른다.

## 7. 멈춤 조건

아래 중 하나면 구현을 멈추고 8절 형식에 "멈춤 보고"를 쓴다. 추측해서 진행하지 않는다.

- 계약·작업·결정 사이의 충돌, 또는 필요한 이름·형식이 어디에도 없음.
- 대상 파일 밖을 고쳐야만 작업이 끝남.
- 같은 테스트 실패를 원인을 모른 채 두 번 고쳐도 계속 실패함.
- 선행 작업의 공개 API가 계약과 다름.
- 의존성 추가, 네트워크 접근, 사람 결정이 필요함.
- 원본 이식 테스트의 기대값이 계약을 따른 구현과 맞지 않음.

멈춤 보고에는 다음 6가지를 이 순서로 쓴다: ① 예상한 결과 ② 실제 결과 ③ 문제라고 본 근거(파일:줄, 명령 출력) ④ 원인(확인한 것과 추정 구분) ⑤ 제안하는 수정 방향 ⑥ 영향 범위.

```text

상태: 완료 | 멈춤
커밋: <해시> <메시지 첫 줄>
바꾼 파일: <경로 목록>
테스트: <실행 명령> → <통과/실패 수>, 전체 <통과/실패 수>
수용 테스트 표 대응: <행 번호 → 테스트 함수 이름>
계약 밖 판단: 없음 | <6절 4번으로 정한 내부 구현 목록>
남은 문제: 없음 | <목록>
(멈춤이면) 멈춤 보고 6항목
```

## 9. 커밋 규칙

- 형식: `<type>(docdb): T<번호> <요약>`. `type`은 `feat`, `test`, `fix`, `docs`, `chore` 중 하나.
- 본문: `계약: C-xx, C-yy` / `결정: Dxx` / `테스트: <명령> → <결과>`.
- 리뷰 지적을 고친 커밋: `fix(docdb): T<번호> review — <요약>`.
- 한 커밋에 두 작업을 섞지 않는다.

## 11. 코드 형태

- 원본 `docctl_llm.py`의 짧고 직접적인 형태를 따른다. 한 줄 120자 이하.
- 클래스는 계약에 있는 것만 만든다(`DocdbError`, `Actor`, 원본에서 이식하는 `DocDB`·`Out`). 그 밖은 함수.
- 전역 변경 가능 상태를 두지 않는다(상수는 대문자).
- 식별자는 영어, 주석·docstring은 한국어, 오류 코드는 영어 대문자, 사람용 안내 문구는 한국어.
- 출력 문자열은 계약에 적힌 형식을 그대로 쓴다. 공백 하나, 구분자 하나도 바꾸지 않는다.

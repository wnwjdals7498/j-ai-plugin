# 작업 일지(work log) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사람·날짜 단위 작업 일지를 로컬에 먼저 쓰고 Plane "작업 일지" 프로젝트로 올리며, `ledger log`·Stop 훅으로 쓰고 `ledger log show`·허브 API로 모아 본다.

**Architecture:** `ledger/worklog.py`가 로컬 기록(형식·검사·잠금·미전송 목록)을, `ledger/worklog_plane.py`가 `adapters.WorklogStore` 규격의 Plane 구현(프로젝트·달 항목·댓글 형식)을 맡는다. `ledger/logcli.py`(명령)와 `hooks/stop.py`(자동 기록 요구)는 이 둘만 쓴다. 허브는 `hubsync.sync_worklog`가 Plane 댓글을 `repo_id = 0` 엔터티로 모으고 `/api/v1/worklog`로 내준다.

**Tech Stack:** Python 표준 라이브러리만, pytest, Plane REST API v1, Claude Code 훅(SessionStart·Stop).

**Spec:** `forge-ledger/docs/superpowers/specs/2026-11-26-worklog-design.md`

**선행:** `2026-11-26-pmt-migration.md`의 Task 1~9가 끝난 뒤 시작한다. 그 계획의 Task 5~9가 `cli.py`·`plane.py`·`session_start.py`·`tests/fakes.py`를 고치기 때문이다. 그 계획의 Task 10(실이전)과는 순서가 상관없다. 번호는 그 계획에 이어 Task 11부터 쓴다.

## Global Constraints

- IP, 접속 주소, 토큰, 계정, 이메일 같은 민감값은 계획·코드·테스트·커밋 메시지에 넣지 않는다. 테스트의 가짜 값은 `.exposure-allow`에 사유와 함께 올린다.
- 외부 패키지를 더하지 않는다. Python 3.10~3.13. 완료 조건은 `bash ci/run-checks.sh all`(검사 7개) 통과. 사용자 메시지·오류는 한국어.
- push·배포·GitHub 쓰기는 사용자가 명시적으로 요청할 때만 한다.
- 원천 표식: `external_source = "forge-ledger-worklog"`. 달 항목 `external_id = "<사용자 id>/<YYYY-MM>"`, 댓글 `external_id = <기록 ID>`(uuid4 hex 32자).
- Plane 프로젝트 이름 `"작업 일지"`, 키는 환경 변수 `FORGE_LEDGER_WORKLOG_PROJECT`(기본 `"WLOG"`). 달 항목 이름 `"<display_name> <YYYY-MM>"`.
- 댓글 HTML: 첫 문단 `<p>[일지] <at> <host> <auto|manual>[ repo=<저장소>][ item=<코드>]</p>`, 이어서 본문 한 줄마다 `<p>…</p>`. 모든 값은 `html.escape`.
- 상수: `MAX_TEXT = 400`, `AUTO_INTERVAL_MINUTES = 60`, `HUB_RECENT_MONTHS = 2`, `HUB_FULL_EVERY_HOURS = 24`, `API_MAX_DAYS = 62`.
- 로컬 파일: `default_state_dir(env)/worklog/<YYYY-MM>.jsonl`, `worklog/sent.json`, `worklog/worklog.lock`. 폴더 0700, 파일 0600. 허브 전체 수집 시각: `default_state_dir(env)/hub-worklog.json`.
- 시각은 기록한 컴퓨터의 현지 시각과 오프셋을 함께 적는다(`2026-11-26T11:25:00+09:00`). 날짜·달 구분도 이 시각을 따른다.
- userConfig: `worklog_project_key`(string, 기본 `"WLOG"`), `worklog_host_label`(string, 기본 `""`), `worklog_auto`(boolean, 기본 true). SessionStart가 각각 `FORGE_LEDGER_WORKLOG_PROJECT`, `FORGE_LEDGER_WORKLOG_HOST`, `FORGE_LEDGER_WORKLOG_AUTO`로 내보낸다.
- 노출 검사(`secrets.find_exposures`)에 걸린 기록은 로컬에도 쓰지 않는다. 출력은 패턴 이름만, 값은 절대 출력하지 않는다.
- 항목 코드가 있어도 그 Plane 항목에 댓글을 따로 달지 않는다(인계는 `ledger work note`의 몫).

## Review Focus

1. 같은 컴퓨터의 두 세션이 동시에 `log add` → 줄이 섞이거나 사라지지 않는다. Task 11에서 고정.
2. 현지 `2026-12-01T00:30:00+09:00` 기록(UTC로는 11월 30일) → `2026-12.jsonl`에 들어가고 12월 1일 조회에 나온다. Task 11에서 고정.
3. Plane 댓글 생성 직후, `sent.json` 저장 전에 끊김 → 다시 올리면 409로 기존 id를 받아 `sent.json`만 채우고 중복은 0건이다. Task 12·13에서 고정.
4. Stop 훅에 transcript가 없거나 깨졌거나 상태 폴더에 쓸 수 없음 → 종료 코드 0(세션 종료를 막지 않음). Task 14에서 고정.
5. 두 컴퓨터가 같은 달 항목을 동시에 처음 만듦 → 늦은 쪽은 409의 기존 id를 쓰고 항목은 1개다. Task 12에서 고정.

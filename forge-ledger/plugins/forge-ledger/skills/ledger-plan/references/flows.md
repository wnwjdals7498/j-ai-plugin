# 작업 종류별 흐름

| 흐름 | 명령 | 만드는 것 | 채우는 문서 | 막는가 |
| --- | --- | --- | --- | --- |
| 신규 착수 | `/forge-ledger:plan new <이름>` | 저장소에 Plane 프로젝트를 하나 붙임(`ledger.yml`). PRD·레퍼런스·단계 항목, cycle "프로토타입", 작업 항목. `.ledger/`가 없으면 뼈대와 "<저장소명> 유지보수" 프로젝트 | 18종 전부. 저장소 범위 문서(구현 1·4·6·8·9)가 이미 있으면 갱신이 필요한지만 묻는다 | 막지 않음 |
| 기능 추가 | `plan feature <이름>` | 플러그인이 규모를 판단해 추천하고 사용자가 고른다(D15). 새 Plane 프로젝트를 고르면 신규 착수 흐름, module을 고르면 기존 프로젝트에 module·기능 PRD 항목·작업 항목, 넘어가면 "<저장소명> 유지보수" 프로젝트에 "미분류" 라벨 작업 항목 | 새 프로젝트: 18종. module: PRD 1·2·6·8·9 필수, 나머지는 영향 목록을 물어 해당하는 것만. 넘어가기: 묻지 않음 | 막지 않음 |
| 유지보수 | `plan fix <Gitea 이슈> [--project 키]` | 기본 프로젝트("<저장소명> 유지보수")에 수정 작업 항목(D16), 이슈와 양방향 링크 | 시작할 때 묻지 않음. 끝날 때 구현 4·8 갱신이 필요한지 한 번 묻는다(NFR-07) | 막지 않음 |
| 결정 | `/forge-ledger:decide` | 이력 한 줄(`.ledger/history.md`, Plane 프로젝트 칸 포함), 결정 항목 | - | 막지 않음 |
| 단계 종료 | `plan phase close [--project 키]` | 이력 줄 phase, 다음 cycle | 구현 1–6 갱신, 구현 7 다음 단계 범위 | **게이트 1** |
| 릴리스 | `plan release <버전>` | 이력 줄 release. 태그와 배포는 사용자가 따로 실행 | 저장소 범위 문서(구현 1·4·6·8·9) 갱신, 전체 검사 | **게이트 2** |

## 기능 규모 판단

| 질문 | "예"이면 |
| --- | --- |
| 목표·성공 지표를 따로 세워야 하는가 | 새 Plane 프로젝트 쪽 |
| 두 cycle 이상 걸릴 것 같은가 | 새 Plane 프로젝트 쪽 |
| 새 외부 연동이나 새 화면 묶음이 생기는가 | 새 Plane 프로젝트 쪽 |
| 저장소 범위 문서(데이터·인증 보안)의 구조가 바뀌는가 | 새 Plane 프로젝트 쪽 |

하나라도 "예"면 새 Plane 프로젝트를, 모두 "아니오"면 기존 프로젝트의 module을 추천한다. 추천과 이유를 보여 주고 사용자가 [새 프로젝트] [module] [넘어가기] 중에서 고른다. 넘어간 항목은 "<저장소명> 유지보수" 프로젝트에 "미분류"로 남고, 나중에 `plan feature`로 다시 판단해 옮긴다. 옮길 때는 새 위치에 작업 항목을 만들고, 원래 항목은 링크를 남기고 닫는다.
